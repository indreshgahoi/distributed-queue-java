# ADR-0001: Use Java 21

## Status

Accepted

## Context

The project is intended to explore distributed queue semantics including:

- delivery ownership
- retries
- leases
- concurrency
- durability
- crash recovery
- replication

The implementation language should expose these concepts clearly without adding unnecessary low-level complexity.

## Decision

Use Java 21.

## Rationale

Java provides:

- mature concurrency primitives
- explicit locking and memory-model semantics
- file and NIO APIs suitable for WAL implementation
- strong testing and profiling support
- sufficient systems-level control for the project

Java also keeps the focus on distributed-system semantics rather than manual memory management.

## Alternatives Considered

### Go

Advantages:

- simple concurrency model
- lightweight goroutines
- simple deployment

Not selected because the project benefits from explicitly modeling queue state transitions rather than leaning heavily on channel-based concurrency.

### Rust

Advantages:

- strong memory safety
- predictable performance
- explicit ownership

Not selected because the additional implementation complexity is not required for the initial learning goals.

### C++

Advantages:

- maximum control over memory and I/O

Not selected because manual memory-management complexity would distract from the primary distributed-systems goals.

## Consequences

Positive:

- simpler development and testing
- mature concurrency tooling
- suitable APIs for later persistence work

Negative:

- GC and runtime behavior may hide some low-level memory-management concerns
- the project will not initially explore manual memory management or allocator behavior
